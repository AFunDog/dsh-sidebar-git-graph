侧边栏里多一页 **Git 图谱**：把当前会话的仓库画成 VS Code 风格的分支/合并关系图，并在它上方给出**工作树改动区**。

## 它做什么

- **工作树改动，VS Code 式两段**：图上方是**更改**与**暂存的更改**（合并中还会多出**合并更改**），每行带状态字母（`M`/`A`/`D`/`R`/`C`/`U`）与增删行数；点一行就地展开它的 diff。
- **一眼看清多分支关系**：并发的每条历史线占一条泳道，分叉/汇出处画贝塞尔曲线，合并提交的圆点更大，当前 HEAD 所在泳道更醒目。
- **每个提交带 ref 芯片**：本地分支 / 远程分支 / 标签。
- **一个工作区，多个仓库**：工作区里同时躺着好几个仓库是常态。头部会长出下拉框列出找到的每个仓库，选择按工作区记忆。发现过程不会跑出工作区，层数、目录数、仓库数、耗时四个闸门都封着。
- **同一个仓库的每个工作树**：下拉框把 `git worktree list` 的每一项都列出来，各带自己的分支，可以自由切换；主工作树、分离头、被 lock 的都有标记。
- **点行看详情**：完整 sha、作者、时间、父提交、参与的 refs，下面是**改动文件清单**，每个文件可以就地展开 patch。合并提交按**第一父提交**比较，标题里会写明。
- **远端信息过期会告诉你**：图谱只画本地仓库，绝不联网。页面直接说明仓库上次 fetch 距今多久、哪些本地分支落后于上游 —— 而不是让你对着图猜。
- **虚拟列表**：窗口内最多 2000 条也只渲染可见行；不是当前标签页时**完全不发请求**。

## 只读承诺

不 checkout、不 commit、不 reset、不 rebase、不 fetch/push、不 add、不 restore、不 `worktree add/remove/prune`。只跑 `rev-parse`、`status`、`for-each-ref`、`log`、`diff`、`worktree list` 六条命令。

## 跟随会话的 worktree 标签

装了并启用 [`@zeng/dsh-session-worktree`](https://github.com/AFunDog/dsh-session-worktree) 时，页面默认画**该会话打了标签的那个工作树**，而不是工作目录碰巧所在的那个仓库。

仓库优先级：**你在下拉里手点的** → **会话的 worktree 标签** → 这个工作区上次记住的仓库 → 工作目录所在的仓库 → 扫到的第一个。页面会说明「正在跟随标签」；用不了时说得更清楚（目录没了 / 不是仓库根 / 出了本页可访问范围）—— **绝不静默换一个仓库还不吭声**。卸载或停用那个插件，行为与以前完全一致。

联动走宿主侧 `ctx.get('sessionWorktree')`（跨插件服务接缝），不做浏览器侧互相 import —— 客户端模块表只认平台 seed 词与各包自己的 id，第三方包之间没有解析通道。

## 与 better-sidebar 的关系

有 `dsh-better-sidebar` 时走它的公开扩展点 `ctx.betterSidebar.registerTab`（页面同时出现在它的 `+` 菜单与设置页「侧边卡片」里，可开关）；缺席时回退到 DSH 原生的 `ctx.sidebarRightTabs` + `sidebar.right.pane.tab`。两条路线注册的是同一个 tab 类型，**装不装都能用**。

## 主题与无障碍

配色全部从主题令牌派生（`--dsw-alias-*`），深浅色模式都跟随。测试里内置一份令牌全量快照：CSS 里用了快照之外的名字就失败 —— 因为写错的令牌会静默走 fallback，表现为「颜色看着不对」而不是报错。
